START WITH A PROBLEM

1. Why do we need classes?

Imagine building a school app. Each student has a name, an age, and a method of introducing themselves. You could keep separate variables such as student1Name, student1Age, student2Name, and so on. That becomes messy very quickly.

String student1Name = "Maya";
int student1Age = 14;

String student2Name = "Arun";
int student2Age = 15;

Now imagine 500 students. Hundreds of separate variables are difficult to organise, pass around, and maintain. We need a way to group related data and the actions that work on that data.

Analogy: a cookie cutter
A class is like a cookie cutter or a product design. It describes what each cookie should look like. An object is one actual cookie made from that cutter. One class can create many objects, and each object can have its own data.

Blueprint: Student

  • name
  • age
  • introduce yourself

The description of what a Student has and can do.

Objects made from it

  • Maya, age 14
  • Arun, age 15
  • Kavi, age 14

Separate instances, each with its own values.

Core idea: a class groups related state (data) and behaviour (methods). An object is a particular instance of that class.
BLUEPRINT VS THING

2. Class vs object

Let's define a simple Dog class. It says every Dog object will have a name and can bark.

class Dog {
    String name;

    void bark() {
        System.out.println(name + " says woof!");
    }
}

This class describes a Dog, but it does not automatically create a particular dog. To create an object, use new.

Dog firstDog = new Dog();
firstDog.name = "Pixel";

Dog secondDog = new Dog();
secondDog.name = "Chutney";

firstDog.bark();  // Pixel says woof!
secondDog.bark(); // Chutney says woof!
Analogy: building from a house plan
The architectural plan is the class. House A and House B are objects built from the plan. Both may have a kitchen and a door, but each house has its own address and paint colour.

Read the object-creation line

Dog firstDog = new Dog();
  • Dog on the left is the variable's type: it can refer to a Dog object.
  • firstDog is the variable name.
  • new Dog() creates a new Dog object.
  • = assigns the object reference to the variable.
Useful wording: a variable such as firstDog holds a reference to an object. For now, think of it as a label that lets your code reach that object.

STATE + BEHAVIOUR

3. Fields and methods

A class commonly contains two kinds of members:

MemberWhat it representsExample
FieldData or state stored by each objectString name;
MethodAn action the object can performvoid bark() { ... }
class Lamp {
    String colour; // field: state
    boolean isOn;  // field: state

    void turnOn() { // method: behaviour
        isOn = true;
    }

    void turnOff() {
        isOn = false;
    }
}
Analogy: a desk lamp
Its colour and whether it is switched on are state. Turning it on and off are behaviours. A good class groups the data and the actions that belong together.

Methods can accept input and return a result

class Calculator {
    int add(int first, int second) {
        return first + second;
    }
}

Calculator calc = new Calculator();
int answer = calc.add(7, 5); // 12

int before add says the method returns an integer. The names inside the parentheses are parameters. return sends the answer back to the caller.

Beginner pitfall: void means the method does not return a value. It can still do something, such as print a message or change an object's state.
SET UP A NEW OBJECT

4. Constructors: give an object its starting values

You can create an object and then assign fields, but it is easy to forget a step. A constructor lets the object receive the information it needs when it is created.

class Student {
    String name;
    int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}

Student maya = new Student("Maya", 14);
Student arun = new Student("Arun", 15);
Analogy: a hotel check-in form
When a guest checks in, the hotel records the guest's name and room details. A constructor is like the check-in step: it helps initialise the new object with the information provided.

Constructor rules to remember

  • The constructor name must exactly match the class name.
  • A constructor has no return type, not even void.
  • It runs when you create an object with new.
  • Constructors can be overloaded, meaning a class can have multiple constructors with different parameter lists.
class Student {
    String name;
    int age;

    Student(String name) {
        this(name, 0); // call the other constructor
    }

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
Default constructor note: if you write no constructor at all, Java provides a no-argument default constructor. Once you define a constructor yourself, Java does not automatically add that default constructor for you.
A USEFUL KEYWORD

5. What does this mean?

Inside an instance method or constructor, this refers to the current object: the particular object whose code is running.

class Student {
    private String name;

    Student(String name) {
        this.name = name;
    }
}

Both the field and the constructor parameter are named name. The parameter is the value coming in. this.name means the field belonging to this object.

Analogy: “my name”
Imagine two students answering a roll call. When Maya says “my name,” she means Maya's name. When Arun says “my name,” he means Arun's name. this means “this particular object here.”

Read the assignment from right to left in plain English: take the incoming parameter name and store it in this object's field this.name.

You will often see this.field = field; in constructors. It is a naming convention, not a mandatory pattern; you can choose different parameter names.
PROTECT THE DATA

6. Encapsulation: keep the rules close to the data

Suppose a bank account has a balance. If every part of a program can change that balance directly, a careless line might set it to a negative value or accidentally overwrite it.

// Risky design: callers can change the balance freely
class BankAccount {
    public double balance;
}

Anyone with access could write account.balance = -5000;. That may violate the rules of a bank account.

Analogy: an ATM
You don't open the ATM and manually spin its internal gears. You use buttons for supported actions: deposit, withdraw, check balance. The ATM controls how those actions happen. Encapsulation gives an object a similar boundary.

Use private fields and public methods

class BankAccount {
    private double balance;

    public BankAccount(double openingBalance) {
        if (openingBalance < 0) {
            throw new IllegalArgumentException(
                "Opening balance cannot be negative"
            );
        }
        balance = openingBalance;
    }

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException(
                "Deposit must be positive"
            );
        }
        balance += amount;
    }

    public boolean withdraw(double amount) {
        if (amount <= 0 || amount > balance) {
            return false;
        }
        balance -= amount;
        return true;
    }
}
  • private means code outside the class cannot access the field directly.
  • public means other code can call that method, subject to the method's rules.
  • getBalance() provides controlled read access.
  • deposit() and withdraw() validate requests before changing the balance.
Encapsulation is more than getters and setters. The key idea is to hide internal details and offer safe operations that preserve the object's rules. A public setter that accepts any value can defeat the purpose.

Access modifier cheat sheet

ModifierBeginner interpretation
privateAccessible only within the declaring class.
publicAccessible from anywhere the class/member is otherwise accessible.
No modifierPackage-private: accessible within the same package.
protectedAccessible within the same package and also in subclasses under Java's protected-access rules.
BUILD A MINI OBJECT

7. Interactive bank account simulator

Let's model the behaviour of our encapsulated bank account. Start with ₹1,000, then deposit or withdraw. Try a negative deposit or a withdrawal larger than the balance and observe the validation.

What would the Java calls look like?

BankAccount account = new BankAccount(1000);
account.deposit(250);
boolean success = account.withdraw(100);

System.out.println(account.getBalance()); // 1150.0

Notice there is no account.balance = .... The field is private, so callers must use the class's public operations. This keeps the account's rules in one place.

Money in real systems: double is used here to keep the lesson focused on objects. Financial applications commonly use BigDecimal or integer minor units (such as paise) to avoid floating-point rounding surprises.
ONE CLASS, SHARED INFORMATION

8. Instance members vs static

Most fields belong to each individual object. A static member belongs to the class itself and is shared at class level.

class Player {
    String name;                  // each player has a name
    static int playerCount = 0;   // shared count

    Player(String name) {
        this.name = name;
        playerCount++;
    }
}

Player p1 = new Player("Maya");
Player p2 = new Player("Arun");
System.out.println(Player.playerCount); // 2
Analogy: classroom desks and the classroom sign
Each student has their own desk (instance data). The classroom has one room number shared by everyone (class-level data). Static members are shared, rather than copied independently into each object.
  • Use instance fields for per-object data, such as each player's name.
  • Use static fields for information shared by the class, such as a counter.
  • Access a static member through the class name, such as Player.playerCount.
Common mistake: a static method has no current object, so it cannot directly use an instance field like name without an object reference.
GOOD CLASS DESIGN

9. A few habits that make classes easier to use

  • Use meaningful names. Class names usually use PascalCase, such as BankAccount; method and variable names usually use camelCase, such as getBalance.
  • Keep fields private by default. Expose only the operations other code actually needs.
  • Keep an object's rules in the class. If a balance must not become negative, make deposit and withdrawal enforce that rule.
  • Construct valid objects. Use constructors to check required information and initialise fields.
  • Keep one class focused. A Student class should not also send emails, render web pages, and connect to every database.
Analogy: a vending machine
A vending machine exposes buttons and accepts payment. You don't need to know how its internal motor works. A well-designed class offers a small, clear public interface and hides the implementation details.

Spot the design issue

Which is better for a bank account?

Design A

public double balance;

Any caller can write any value.

Design B

private double balance;
public void deposit(double amount) {
    // validate, then update
}

The class controls changes.

Better choice: Design B, because it protects the object's invariant (a rule that should always remain true).

PRACTICE

10. Practice problems

Try each problem before revealing the explanation.

1. In your own words, what is the difference between a class and an object?

A class is a blueprint describing fields and methods. An object is a particular instance created from that blueprint.

2. What does new Student("Maya", 14) do?

It creates a Student object and calls the matching constructor with the values "Maya" and 14.

3. Why does a constructor have no return type?

A constructor is a special initialisation mechanism, not an ordinary method. Its name matches the class and it has no declared return type.

4. In this.name = name;, what does this.name mean?

The name field belonging to the current object. The right-hand name is the parameter.

5. Why should a bank account's balance usually be private?

To prevent callers from changing it directly and bypassing rules. Public methods can validate deposits and withdrawals.

6. Does void turnOn() return a value?

No. It can perform an action or change state, but it does not return a result to the caller.

7. What is one difference between an instance field and a static field?

Each object has its own instance field. A static field belongs to the class and is shared at class level.

8. Why is a public setter that accepts any balance value not enough for encapsulation?

It still lets callers violate the account's rules. Encapsulation requires controlled operations and validation, not merely getters and setters.
