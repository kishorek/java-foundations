1. Why do exceptions exist?

Imagine a food delivery app. Most orders work normally. But what if the address is missing, payment is declined, or the restaurant is closed? A good app does not simply crash; it explains the problem and gives the user a useful next step.

🧯
Analogy: a fire alarm and emergency plan

An exception is like an alarm that says, “The normal plan cannot continue.” A catch block is the emergency plan. It should handle the situation, not hide every alarm under the carpet.

int seats = 0; // This calculation is legal, but the result may not make sense. int peoplePerCar = 12 / seats; // ArithmeticException

Some errors are predictable and should be prevented with ordinary checks. Other failures are represented by exceptions. Good code uses both: validate what you can, and handle failures that can still occur.

Prevent a problem

Check whether a divisor is zero before dividing, or whether a value is valid before using it.

Recover from a failure

Catch a file-reading failure and tell the user which file could not be opened.

Key idea: an exception is not automatically a bug in the language. It is Java's way of representing an unusual condition that interrupts the normal path.

2. try and catch: attempt and recovery

Put code that might fail inside try. Put the response for a particular failure inside catch.

try { int result = 10 / 0; System.out.println(result); } catch (ArithmeticException e) { System.out.println("You cannot divide by zero."); } System.out.println("Program continues.");
  1. Java enters the try block and runs statements in order.
  2. If no exception occurs, the catch block is skipped.
  3. If a matching exception occurs, Java stops the remaining statements in that try block and looks for a matching catch.
  4. After the handler completes, execution continues after the try/catch statement, if the exception was handled.

3. Exception types: not every problem is the same

Java organizes throwable conditions into a hierarchy. You do not need to memorize every class today; understand the major branches first.

Throwable ├── Error // serious JVM/system-level problems └── Exception ├── RuntimeException // unchecked exceptions └── other exceptions // often checked exceptions

Checked exception

The compiler requires you to catch it or declare it with throws. Example: IOException.

Unchecked exception

A RuntimeException subclass. You are not forced by the compiler to catch it. Examples: NullPointerException, IllegalArgumentException.

Error

Usually represents a serious condition outside normal application recovery. Example: OutOfMemoryError.

🏫
Analogy: school permissions

A checked exception is like a permission slip the school requires you to submit or formally account for. An unchecked exception is like an unexpected mistake that can still happen even without a required form. An Error is closer to a major building issue, not a routine classroom problem.

ExampleTypical meaningCategory
IOExceptionA read/write operation failedChecked
FileNotFoundExceptionA requested file cannot be found/openedChecked

NumberFormatExceptionA string cannot be parsed as the requested numberUnchecked
NullPointerExceptionCode tries to use a null reference as an objectUnchecked
Beginner rule: do not write catch (Exception e) everywhere just to silence errors. Catch the types you can meaningfully handle, and preserve enough information to diagnose unexpected failures.

4. Control flow: what runs, and what gets skipped?

Once an exception happens inside a try, the rest of that same try block is skipped. Java searches for a compatible handler.

System.out.println("A: before"); try { System.out.println("B: start try"); int value = Integer.parseInt("oops"); System.out.println("C: value = " + value); // skipped } catch (NumberFormatException e) { System.out.println("D: invalid number"); } System.out.println("E: after handler");
Press Play to trace the statements.

Multiple catch blocks

try { // operations that can fail } catch (FileNotFoundException e) { // specific file problem } catch (IOException e) { // other input/output problem }

Order matters: put the more specific exception before the broader parent type. If IOException came first, the later FileNotFoundException handler would be unreachable because the broader handler already catches it.

5. throw vs throws

They look similar but have different jobs.

throw

Actually raise one exception

Use it inside a method or block when your code detects an invalid situation.

if (age < 0) { throw new IllegalArgumentException( "Age cannot be negative"); }
throws

Declare a possibility

Use it in a method signature to tell callers that a checked exception may escape.

static String loadText(Path path) throws IOException { return Files.readString(path); }
📣
Analogy: raising a flag vs posting a warning

throw raises the flag right now. throws posts a warning on the method's door: “Calling this may bring an IOException; be prepared to handle it or pass it along.”

Which declaration is correct?

Scenario: a method calls Files.readString(path) and lets the caller handle the checked I/O failure. What should the method signature include?

You can also define your own exception class for a domain-specific problem, but start by using standard exception types when they clearly describe the issue.

class InvalidOrderException extends Exception { InvalidOrderException(String message) { super(message); } }

6. finally and try-with-resources

Some operations use resources that should be closed, such as files, readers, network connections, and database connections.

finally

try { System.out.println("Do the work"); } catch (IOException e) { System.out.println("Handle the I/O problem"); } finally { System.out.println("Cleanup step"); }

A finally block normally runs whether the try succeeds or a handled exception occurs. It is often used for cleanup, though abrupt JVM termination can prevent it from running.

Modern Java: try-with-resources

try (BufferedReader reader = Files.newBufferedReader(path, StandardCharsets.UTF_8)) { String line; while ((line = reader.readLine()) != null) { System.out.println(line); } } catch (IOException e) { System.out.println("Could not read the file: " + e.getMessage()); }
Why this is better: Java automatically closes a resource that implements AutoCloseable when the try-with-resources statement finishes, including when an exception occurs. This is generally safer than manually closing in a finally block.
🔑
Analogy: borrow a library book

You use the book, then return it even if your study session gets interrupted. Try-with-resources makes the “return it” step automatic.

7. Files and paths: where is the data?

A file is stored data that can outlive one program run. A path is the address Java uses to locate it.

Relative path

data/marks.txt

Resolved from the program's current working directory. It is not automatically relative to the Java source file.

Absolute path

/home/student/data/marks.txt

A full location from the root of the file system. Windows paths look different, for example C:\\school\\marks.txt.

Modern Java file APIs are in java.nio.file. Path represents a location, while Files provides operations such as reading, writing, checking existence, and copying.

import java.nio.file.Path; import java.nio.file.Files; import java.nio.charset.StandardCharsets; import java.io.IOException; Path file = Path.of("data/marks.txt"); if (Files.exists(file)) { System.out.println("File exists"); }
Security note: do not trust a file path supplied by a user without validation. In real applications, restrict access to the intended folder, handle permissions carefully, and avoid overwriting important files by accident.

8. Read and write files with Java

For small text files, Files.readString and Files.writeString are convenient (Java 11+). For larger files, process the content line by line with a buffered reader rather than loading everything into memory.

Read a small file

try { String content = Files.readString( Path.of("notes.txt"), StandardCharsets.UTF_8); System.out.println(content); } catch (IOException e) { System.out.println("Reading failed: " + e.getMessage()); }

Write a text file

try { Files.writeString( Path.of("summary.txt"), "Java practice completed\\n", StandardCharsets.UTF_8); } catch (IOException e) { System.out.println("Writing failed: " + e.getMessage()); }

writeString creates a file if needed and, by default, replaces existing content. To append instead, pass StandardOpenOption.CREATE and StandardOpenOption.APPEND.

Files.writeString( Path.of("log.txt"), "New event\\n", StandardCharsets.UTF_8, StandardOpenOption.CREATE, StandardOpenOption.APPEND);

10. Practice problems

Try to solve each one before revealing the suggested answer. These are designed to test understanding, not memorization.

1. Predict the output. What prints after this code catches the exception?

try { int n = Integer.parseInt("cat"); System.out.println("A"); } catch (NumberFormatException e) { System.out.println("B"); } System.out.println("C");
Answer: B, then C. Parsing throws before A can print; the catch handles it and execution continues after the try/catch.

2. Checked or unchecked? Classify IOException and NullPointerException.

Answer: IOException is checked. NullPointerException is unchecked because it extends RuntimeException.

3. Choose the keyword. Which keyword declares that a method may pass an IOException to its caller?

Answer: throws, used in the method signature. throw is used to raise a particular exception.

4. Fix the catch order. You need separate handlers for FileNotFoundException and IOException. Which comes first?

Answer: FileNotFoundException first, then IOException, because the former is more specific.

5. Avoid resource leaks. What is the recommended way to ensure a BufferedReader closes automatically?

Answer: Use try-with-resources: try (BufferedReader reader = ...). Java closes the reader at the end of the statement.

6. Read a small file. Which API reads the entire text file into one String in Java 11+?

Answer: Files.readString(path, StandardCharsets.UTF_8). Remember to handle IOException.

7. Replace vs append. What must you add when writing new text to the end of a file?

Answer: Pass StandardOpenOption.APPEND, usually with StandardOpenOption.CREATE if the file should be created when missing.

8. Design a safe file importer. A marks file contains lines 70, bad, 95. What are two different errors you might need to handle?

Answer: A file-level IOException if it cannot be read, and a line-level NumberFormatException for bad. They represent different problems and should have different responses.
