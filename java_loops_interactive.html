Lesson 1

Why do we need loops?

Loops let you repeat the same kind of instruction without writing it again and again.

🧹

Imagine sweeping a classroom. You would not write a separate instruction for every square of the floor. You repeat the sweeping action until the floor is clean. A loop gives Java a repeatable instruction and a rule for when to stop.

Without a loop versus with a loop

Without a loop

System.out.println(1); System.out.println(2); System.out.println(3); System.out.println(4); System.out.println(5);

Repeated code becomes long and difficult to maintain.

With a loop

for (int i = 1; i <= 5; i++) { System.out.println(i); }

One compact instruction prints all five numbers.

Every loop needs a plan: decide where it starts, when it should continue, and how its state changes so that it can eventually stop.
Lesson 2

The for loop: repeat a known number of times

A for loop is especially useful when you know how many repetitions you need, such as counting from 1 to 5.

🏃

Think of running five laps. You start at lap one, keep going while the lap number is at most five, and increase the lap counter after each lap. The for loop puts these three parts together in one line.

Explore the three parts

for (int i = 1; i <= 5; i++) { System.out.println(i); }
1

Create the counter and begin at 1.
2
Condition: i <= 5
Check whether the loop should run again.
3
Update: i++

Lesson 3

The while loop: keep going while true

A while loop checks its condition before each iteration. If the condition is false at the start, the body never runs.

🪣

Imagine filling a bucket. While the bucket is not full, keep pouring water. Before every pour, check whether there is still room. If it is already full, the loop does not pour at all.

Watch the condition control the loop

int water = 0; while (water < 3) { System.out.println("Pour water"); water++; }

The variable changes inside the loop, so the condition eventually becomes false. If you remove water++, the condition stays true and the loop never stops.

Remember: a while loop is a good fit when you want to repeat something until a condition changes, even when you do not know the exact number of iterations in advance.
Lesson 4

The do while loop: run once before checking

A do while loop executes its body first, then checks the condition. This means it always runs at least once.

🍪

Imagine tasting a new cookie before deciding whether to have another. You take the first bite, then decide whether to continue. Even if you decide not to continue, that first bite already happened.

Compare the order

while

1
Check condition.
2
Run body only if true.
May run zero times

do while

1
Run body first.
2
Check condition afterwards.
Runs at least once

Try a condition that starts false

If the starting value is 5 and the condition is “value is less than 3”, compare how many times each loop prints.

while (value < threshold)
0 runs
Condition is checked first.
do { ... } while (value < threshold)
1 run
Body runs before the condition check.
With the starting values above, while skips the body and do while runs once.
int value = 5; do { System.out.println(value); value++; } while (value < 3);
Syntax detail: the do while statement ends with a semicolon after the condition, as in while (condition);. That final semicolon is required.
Lesson 5

Which loop should you choose?

All three repeat code, but their structure helps you express different intentions clearly.

for

Best when the number of repetitions is known or a counter controls the loop.

Print 1 to 10

while

Best when you check a condition before every repetition and may run zero times.

Read until input is valid

do while

Best when the body must run at least once before the condition is checked.

Show a menu, then ask again

break and continue

break exits a loop. continue skips the rest of the current iteration and moves toward the next one.

Control the loop flow

Choose a loop for the scenario

Avoid infinite loops: confirm that the condition can eventually become false. A loop such as while (true) is intentional only when you provide a suitable exit, such as a break statement.
