1. Start with a problem, not a definition

Imagine you're building a school event registration app. Students sign up online. What could go wrong if you store every sign-up in a plain list?

  • Arun signs up three times. Should the guest count include Arun three times?
  • The teacher asks, “What score did Maya get?” Should you scan every student record manually?
  • The school shop wants to know how many notebooks are in stock for each product.
Analogy: two different jobs at a school event
Guest list: you care whether a name is present, and you want each name only once. This is a Set job.
Registration notebook: each student ID points to details such as a score or email. This is a Map job.

Question A: “Is Arun on the list?”

Use a Set when membership and uniqueness matter.

Set<String> guests;

Question B: “What is Maya's score?”

Use a Map when one key should lead to a value.

Map<String, Integer> scores;
Today's mental model: Set = a bag of unique items. Map = a labelled lookup table. Don't worry about memorising every method yet; first learn when each structure solves a problem.

2. Collections recap: array, list, Set and Map

You have already seen arrays and lists. They are useful, but not every problem is about keeping items in a numbered sequence.

StructureThink of it asMain strengthExample question
ArrayNumbered seatsFixed-size sequence; access by indexWho is in seat 2?
ArrayListA growing queue/listOrdered items; duplicates allowedWhat is the next task?
SetGuest listUnique itemsHas this email already been used?
MapDictionary or labelled lockersLook up a value by keyWhat is product X's stock?
Quick analogy
An array/list is like a row of boxes where position matters. A Set is like a list of distinct names. A Map is like a dictionary: look up a word (key) to find its meaning (value).

Set and Map are part of Java's Collections Framework family, but there is an important detail: Map is part of the framework, yet it is not a subtype of Collection. It stores pairs, not individual elements.

PART 1 · UNIQUE ITEMS

3. Meet Set: the guest list that rejects duplicates

A Set is a collection that does not keep duplicate elements. In beginner code, the most common implementation you'll meet first is HashSet.

First, read this tiny program

import java.util.HashSet;
import java.util.Set;

public class GuestList {
    public static void main(String[] args) {
        Set<String> guests = new HashSet<>();

        guests.add("Arun");
        guests.add("Maya");
        guests.add("Arun"); // already present

        System.out.println(guests.size());       // 2
        System.out.println(guests.contains("Maya")); // true
    }
}

Line by line:

  1. Set<String> says the collection will hold String values. The angle brackets describe the type of item.
  2. new HashSet<>() creates the actual Set object. The diamond <> lets Java infer the type from the declaration.
  3. add("Arun") adds Arun if he isn't already there.
  4. Adding Arun a second time does not make another Arun entry.
  5. size() returns the number of unique elements, which is 2 in this example.
Analogy: the bouncer at a party
The bouncer checks whether a name is already on the guest list. If it is, the name isn't added again. The Set cares that Arun is present; it does not keep a tally of how many times Arun tried to enter.

The essential Set methods

MethodPlain EnglishExample
add(value)Try to add a valueguests.add("Maya");
contains(value)Ask whether it is presentguests.contains("Arun");
remove(value)Remove it if presentguests.remove("Arun");
size()Count unique elementsguests.size();
isEmpty()Check whether there are zero elementsguests.isEmpty();

What does add return?

add() returns a boolean: true if the Set changed because the value was added, and false if the value was already there.

boolean firstTry = guests.add("Kavi"); // true if new
boolean secondTry = guests.add("Kavi"); // false: duplicate
Use a Set when: you need unique usernames, unique tags, distinct product IDs, visited web pages, or a fast “have I seen this already?” check.
Important: a HashSet does not promise insertion order or alphabetical order. If you print it, the order may surprise you. Don't rely on it.

PART 2 · KEY → VALUE

5. Meet Map: a label that leads to information

A Map stores key-value pairs. You provide a key, and the Map connects it to a value. A key can appear only once in a Map, although multiple keys can have the same value.

Analogy: a row of labelled lockers
The locker label is the key; what is inside is the value. Locker 17 can have its contents replaced, but you don't create a second locker with the same label 17 inside the same Map.

Example: student scores

import java.util.HashMap;
import java.util.Map;

Map<String, Integer> scores = new HashMap<>();

scores.put("Maya", 92);
scores.put("Arun", 85);
scores.put("Maya", 96); // replace Maya's old score

System.out.println(scores.get("Maya")); // 96
System.out.println(scores.size());      // 2

Notice what happened: the second put("Maya", 96) updated Maya's score. It did not add a second Maya key, so the Map still has two entries.

Key and value types

Map<String, Integer> scores;
Map<String, String> phoneNumbers;
Map<Integer, String> studentNames;
  • Map<String, Integer>: key is a String; value is an Integer.
  • Map<String, String>: both key and value are Strings.
  • Map<Integer, String>: key is an Integer; value is a String.
Why Integer and not int? Generic type parameters use reference types. Java provides wrapper classes such as Integer for primitive int. Java automatically converts between many primitive and wrapper uses through boxing and unboxing.

The essential Map methods

MethodPlain EnglishExample
put(key, value)Add a pair or update an existing keyscores.put("Maya", 96);
get(key)Get the value for a keyscores.get("Maya");
getOrDefault(key, fallback)Get the value, or a fallback if the key is missingscores.getOrDefault("Kavi", 0);
containsKey(key)Check whether the key existsscores.containsKey("Arun");
containsValue(value)Check whether any entry has this valuescores.containsValue(85);
remove(key)Remove the key and its valuescores.remove("Arun");
size()Count key-value pairsscores.size();
Missing keys: with a normal HashMap, get("Kavi") returns null when Kavi is absent. Don't immediately assign that result to primitive int and assume it exists; unboxing null can cause a NullPointerException. Use getOrDefault or check the key first.

7. How do we loop through a Set or Map?

You already know the enhanced for loop. It works nicely with Sets because each pass gives you one element.

Loop through a Set

Set<String> guests = new HashSet<>();
guests.add("Arun");
guests.add("Maya");

for (String guest : guests) {
    System.out.println(guest);
}

The loop visits each unique guest. Since this is a HashSet, don't assume which guest prints first.

Loop through a Map

for (Map.Entry<String, Integer> entry : scores.entrySet()) {
    String name = entry.getKey();
    Integer score = entry.getValue();
    System.out.println(name + " scored " + score);
}
Analogy: opening every locker
entrySet() gives you each labelled locker record. getKey() reads the label; getValue() reads the contents. You get both pieces together.

Quick check

If you only need to know whether a Set contains an email, do you need to loop through every item yourself?

No. Call emails.contains("person@example.com"). Let the Set do the membership check.
PUT IT TO WORK

8. Three useful real-world patterns

Pattern A: remove duplicates from a list

Suppose a CSV import contains the same email more than once. A Set can keep just the distinct emails.

import java.util.Arrays;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

List<String> emails = Arrays.asList(
    "a@example.com", "b@example.com", "a@example.com"
);
Set<String> uniqueEmails = new HashSet<>(emails);

System.out.println(uniqueEmails.size()); // 2

If you need to preserve the order in which emails first appeared, use a LinkedHashSet instead.

Pattern B: count how often each word appears

This is a classic Map use case. A Set would only tell us whether a word exists; a Map can store the count for every word.

String[] words = {"tea", "coffee", "tea", "juice", "tea"};
Map<String, Integer> counts = new HashMap<>();

for (String word : words) {
    int oldCount = counts.getOrDefault(word, 0);
    counts.put(word, oldCount + 1);
}

// tea → 3, coffee → 1, juice → 1
  1. Read the current count for this word.
  2. If it has never appeared, treat its count as zero.
  3. Add one to the count.
  4. Store the updated count back under the same key.
Analogy: tally marks at a café
Each drink name is a key. Its count is the value. Every time someone orders tea, update the tea counter from 2 to 3.

Pattern C: count unique visitors

Set<String> visitors = new HashSet<>();
visitors.add("user-17");
visitors.add("user-21");
visitors.add("user-17");

System.out.println(visitors.size()); // 2 unique visitors

One important design decision: if you need to know how many visits each person made, use a Map of visitor ID to count, not just a Set.

CHOOSING WISELY

9. Which implementation should I choose?

Set and Map describe what operations are available. Classes such as HashSet and HashMap are concrete implementations that do the work.

NeedConsiderWhy
Unique items; order doesn't matterHashSetCommon general-purpose choice
Unique items; keep insertion orderLinkedHashSetIterates in insertion order
Unique items; sorted orderTreeSetKeeps elements sorted
Key-to-value lookup; order doesn't matterHashMapCommon general-purpose choice
Key-to-value lookup; insertion orderLinkedHashMapIterates in insertion order by default
Key-to-value lookup; sorted keysTreeMapKeeps keys sorted
Don't overthink performance on day one. Start with HashSet or HashMap for ordinary uniqueness and lookup tasks. Choose a different implementation when your program needs a specific ordering behaviour.

One last distinction

  • Set elements are unique.
  • Map keys are unique, but values may repeat.
  • A Map is not a Set of values: it connects keys to values.
  • Hash-based collections do not guarantee sorted or insertion order.

10. Practice problems

Try to answer each one before revealing the explanation. The goal is to choose the right structure and reason about its behaviour.

1. A website must ensure each username is registered only once. Which structure fits best?

A Set<String>, such as a HashSet<>. It prevents duplicate username values within that Set.

2. What is the size after this code runs?

Set<String> s = new HashSet<>();
s.add("red"); s.add("blue"); s.add("red");
The size is 2. The second "red" is a duplicate.

3. A Map contains "Maya" → 92. What happens after scores.put("Maya", 96)?

Maya's value is updated to 96. The Map does not create a second Maya key.

4. Declare a Map where a product code is a String and its stock quantity is an Integer.

Map<String, Integer> stock = new HashMap<>(); with imports for Map and HashMap.

5. What does scores.getOrDefault("Kavi", 0) return when Kavi is not a key?

It returns the fallback value 0.

6. You need to count how many times each word appears in a document. Use a Set or a Map?

Use a Map<String, Integer>. Each word is a key and its occurrence count is the value.

7. Which implementation would you consider if unique items must be iterated in insertion order?

LinkedHashSet.

8. Can two different keys in a Map point to the same value?

Yes. Keys must be unique, but values can repeat. For example, both Arun and Maya could have a score of 90.
