Array Indexing and Bounds

Stage 4 Concept ⏱ 12 min 📖 Glossary

Index 0 is first, length−1 is last, and anything else is a door that does not exist. Java guards every knock — wrong doors don’t return garbage, they detonate loudly.

🔎 Motivating questionWhy do some countries skip “floor 0” while programmers worship it?

Objectives

  • Use 0-based indexes
  • Explain length vs last index
  • Avoid out-of-bounds

Needs first: Arrays

1 Start with an analogy

Real life first, code second.

The hotel with floors 0–4 (five floors). The top floor is floors − 1 = 4. Knock on floor 9 and security (ArrayIndexOutOfBoundsException) escorts you out — no fake rooms, no polite lies.

⚠️ Where the analogy breaksWhere it breaks: hotels sometimes forgive trespassers. Java NEVER forgives out-of-bounds: instant exception, exact line number, every time. The strictness is the feature.

2 The concept, plainly

One idea at a time, words before jargon.

First slot = 0, last slot = length − 1. The universal safe loop is for (i = 0; i < a.length; i++) — strict <, never <=.

a[a.length] ALWAYS crashes: the highest door number is one less than the count. Off-by-one here is the most common array bug in existence.

Arrays use a.length (a FIELD, no brackets); Strings use s.length() (a METHOD). Mixing them up is a rite of passage — now you are vaccinated.

Bounds are checked at RUNTIME on every access: safety costs a nanosecond and saves days of “why is my data weird” (other languages return garbage instead).

⚙️ Tech details — precise facts
  • The exception names the crime: ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3 — read it, go to the line, fix the index.
  • Negative indexes are equally illegal: a[-1] crashes. (Python-style wrap-around does NOT exist in Java.)
  • Enhanced for-loops (for (int v : a)) cannot go out of bounds BY CONSTRUCTION — one reason pros prefer them for reading.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
public class Main {
  public static void main(String[] args) {
    int[] a = {5, 6, 7};
    System.out.println("first = " + a[0]);
    System.out.println("last = " + a[a.length - 1]);
    System.out.println("doors = " + a.length);
    // System.out.println(a[3]); // door 3 missing: CRASH
  }
}
▶ Output first = 5 last = 7 doors = 3
  • First door is 0, always.
  • Last door is length − 1, always.
  • Door 3 on a 3-long array does not exist.
▶️ Run it yourselfSave exactly as Main.java, then javac Main.java and java Main. Every full program in this course works this way.
💡 Why this output?Length 3 means doors 0, 1, 2 exist. Door 3 stays commented — uncomment it to meet the exception personally.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: for (i = 0; i <= a.length; i++)Why: Visits one ghost door past the end — crashes on the final round, every time.
✅ Fix: Strict less-than: i < a.length. Tattoo it.
❌ Mistake 2: a.length() with brackets on an array.Why: Arrays expose length as DATA; only Strings (and friends) compute length().
✅ Fix: a.length for arrays, s.length() for strings.
❌ Mistake 3: Assuming the last index equals the length.Why: The eternal off-by-one: 3 doors means top door 2.
✅ Fix: Last = length − 1. Say it aloud.
❌ Mistake 4: Catching the exception to “handle” a wrong index.Why: Masks the bug — the index math is still wrong underneath.
✅ Fix: Fix the INDEX, don’t sedate the symptom.
