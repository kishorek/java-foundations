Basic Algorithms: Search, Count, Min/Max

Stage 4 Practice ⏱ 20 min 📖 Glossary

Four tiny superpowers from ONE loop skeleton: find the biggest, find the smallest, count the matches, locate an item. Learn the skeleton once; the “memory” you keep is the only thing that changes.

🔎 Motivating questionHow do you find the tallest student in a line without measuring anyone twice?

Objectives

  • Find min/max in an array
  • Count matches
  • Write linear search

Needs first: StringBuilder

1 Start with an analogy

Real life first, code second.

The trophy walk. Crown the first student champion (best so far), walk the line, swap crowns whenever someone taller appears. Counting = clicker per match. Searching = stop at the first name called.

⚠️ Where the analogy breaksWhere it breaks: an EMPTY line has no first student — crowning a[0] of nothing crashes. Empty input is the edge case every algorithm must answer.

2 The concept, plainly

One idea at a time, words before jargon.

Max/min: crown best = a[0], tour the REST, swap on strictly-better. Initializing to 0 instead breaks on all-negative inputs — crown a REAL contender.

Counting: clicker c = 0, c++ on every match. Linear search: walk, return the index on match, −1 for “absent” (−1 can never be a valid index, so it is unambiguous).

Stop early when the answer is final: search returns the moment it finds; max/min must finish the whole line (a taller student could be last).

All three share ONE skeleton: init memory → tour every slot → update memory → report. New problem? Same skeleton, different memory. That is the transferable skill.

⚙️ Tech details — precise facts
  • These are O(n): work grows linearly with input size — twice the students, twice the steps. Your first complexity class, felt not memorized.
  • Sentinel values: −1 for “not found”, 0 for “none counted”. Pick values OUTSIDE the answer domain so “absent” never mimics a result.
  • Empty arrays need an explicit decision: throw, return −1/Optional, or require non-empty. “a[0] and pray” is the bug.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
public class Main {
  public static void main(String[] args) {
    int[] a = {4, 9, 2, 9};
    int max = a[0];   // crown the first contender
    int count9 = 0;   // clicker for nines
    int pos2 = -1;    // sentinel: not found yet
    for (int i = 0; i < a.length; i++) {
      if (a[i] > max) max = a[i];
      if (a[i] == 9) count9++;
      if (a[i] == 2) pos2 = i;
    }
    System.out.println("max = " + max);
    System.out.println("nines = " + count9);
    System.out.println("first 2 at = " + pos2);
  }
}
▶ Output max = 9 nines = 2 first 2 at = 2
  • The champion starts as a REAL element, not 0.
  • Each slot is tested once, three memories updated.
  • Results: max 9, two nines, 2 sits at index 2.
▶️ Run it yourselfSave exactly as Main.java, then javac Main.java and java Main. Every full program in this course works this way.
💡 Why this output?One walk collects three answers — same skeleton, three different memories. 4 crowns, 9 dethrones, 2 and 9 counted and located.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: max = 0 “to be safe” with all-negative data.Why: 0 outranks −5 — the “champion” never fought anyone.
✅ Fix: Crown a real contender: max = a[0].
❌ Mistake 2: Crowning a[0] of an EMPTY array.Why: No first student exists — crash on step one.
✅ Fix: Decide empty up front: if (a.length == 0) ... handle.
❌ Mistake 3: Returning 0 for “not found”.Why: 0 LOOKS like “found at slot 0” — ambiguity bug.
✅ Fix: Sentinel −1: outside every valid index.
❌ Mistake 4: Counting with an uninitialized clicker.Why: Locals have no defaults — compile error.
✅ Fix: int count = 0; before the tour.

9 Takeaways + next step

  • One skeleton: init memory → tour → update → report.
  • Crown real contenders; sentinel −1 means absent.
  • Decide the empty case explicitly.
  • Feel O(n): double input, double steps.
