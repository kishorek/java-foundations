Type Conversion and Casting

Stage 2 Concept ⏱ 14 min 📖 Glossary

Sometimes a big value must fit a small box (narrowing) or a small one joins big math (widening). Java is picky — explicitly cast when you might lose something.

🔎 Motivating questionWhat happens pouring a bucket into a mug?

Objectives

  • Tell widening from narrowing
  • Cast safely with (int)
  • Predict truncation

Needs first: Literals and Constants

1 Start with an analogy

Real life first, code second.

Funnel vs bucket. Widening (mug → bucket, int → long) always fits, automatic. Narrowing (bucket → mug, double → int) spills — you must sign “I accept spills” with (int).

⚠️ Where the analogy breaksWhere it breaks: funnels do not round — they chop. (int) 3.99 = 3, not 4. Casting truncates toward zero.

2 The concept, plainly

One idea at a time, words before jargon.

Widening automatic: int → long → double. No loss, no cast.

Narrowing needs cast: (int) 3.9 → 3, (byte) 130 → -126. Data may change!

byte/short/char math becomes int. Division: 5/2 = 2 (int), 5/2.0 = 2.5.

3 Watch it move: Bucket vs mug

Step at your pace. Text explains every move.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
int a = 5, b = 2;
System.out.println(a / b);     // 2 (int!)
System.out.println(a / 2.0);   // 2.5
double d = 3.99;
int n = (int) d;              // 3, chopped
System.out.println(n);
▶ Output 2 2.5 3
  • int/int stays int — truncation.
  • One double lifts math to double.
  • Cast chops, never rounds.
💡 Why this output?Integer division truncates. 2.0 widens the expression. (int) chops .99.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: double avg = sum / count; (both int)Why: Right side truncates before storing!
✅ Fix: double avg = (double) sum / count;
❌ Mistake 2: int n = 3.9;Why: Narrowing needs explicit permission.
✅ Fix: int n = (int) 3.9; // 3
❌ Mistake 3: Expecting (int) to round.Why: It chops toward zero.
✅ Fix: Round: (int) Math.round(3.9); // 4
