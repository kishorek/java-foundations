ArrayList and HashMap

Stage 6 Practice ⏱ 18 min 📖 Glossary

Your two daily drivers, mastered: ArrayList (the growable queue) and HashMap (the ticket shelf). Six methods each covers nearly all real-world use.

🔎 Motivating questionHow do you run a canteen line AND a locker room at once?

Objectives

  • Use ArrayList add/get
  • Use HashMap put/get
  • Loop entries safely

Needs first: Collections: List, Set, Map

1 Start with an analogy

Real life first, code second.

Canteen tray line (ArrayList: add, get, set, remove, size) plus locker tickets (HashMap: put, get, containsKey, remove, keySet). Trays SHIFT when one leaves mid-line; lockers never shift — different physics.

⚠️ Where the analogy breaksWhere it breaks: pulling the FIRST tray forces everyone to shuffle forward (linear cost). And lockers demand GOOD tickets: mutable keys whose hash changes mid-stay lose their coats forever.

2 The concept, plainly

One idea at a time, words before jargon.

ArrayList: add(v), add(i,v), get(i), set(i,v), remove(i), size(). Grows automatically; get is instant; front-removal shuffles everyone behind.

HashMap: put(k,v), get(k) (null when absent!), getOrDefault(k, d), containsKey(k), remove(k), keySet and entrySet. NO order promise.

Missing keys return null: unboxing that null into an int detonates with NullPointerException. Default armor: getOrDefault(k, 0).

Loop maps via entrySet (both sides at once); NEVER structurally edit inside for-each (ConcurrentModificationException) — use removeIf or an Iterator.

⚙️ Tech details — precise facts
  • ArrayList grows about 1.5x when full (amortized cheap adds); remove(0) is linear — Deques serve queue-duty better.
  • HashMap hashes keys to buckets: good hashCode means even spread and near-instant gets. Mutating a stored key’s hash fields loses the entry.
  • entrySet loop: for each entry, getKey plus getValue — one pass, both sides, no re-lookup.

Step at your pace. Text explains every move.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
List<String> line = new ArrayList<>();
line.add("Ada");
line.add("Bob");
Map<String, String> locker = new HashMap<>();
locker.put("A1", "Ada bag");
// line.get(0)="Ada"  locker.get("A1")="Ada bag"
// line.size()=2  locker.containsKey("A1")=true
▶ Output Ada plus Ada bag, then size 2 and hasA1 true.
  • Growable line: two join.
  • Ticket shelf: A1 maps to bag.
  • Indexed AND keyed retrieval side by side.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: line[0] brackets on a List.Why: Lists are objects with METHODS — brackets are array syntax.
✅ Fix: line.get(0). Brackets for arrays, methods for Lists.
❌ Mistake 2: int n = map.get("missing") — unboxing null.Why: Absent gives null; auto-unbox detonates with NPE.
✅ Fix: map.getOrDefault("missing", 0) — armor by default.
❌ Mistake 3: map.remove(k) inside for-each over keySet.Why: Structural edit mid-tour: ConcurrentModificationException.
✅ Fix: removeIf with a condition, or an explicit Iterator.
❌ Mistake 4: Expecting HashMap to print in insertion order.Why: No order promise — today’s order is coincidence.
✅ Fix: Need order? LinkedHashMap preserves insertion.

HintZero-based throughout.

Word counter

HintgetOrDefault plus 1.
Solutionfor each w: count.put(w, count.getOrDefault(w, 0) + 1);
