Arrays

Stage 4 Concept ⏱ 16 min 📖 Glossary

An egg tray holds exactly 12 eggs — identical slots, numbered positions, zero growth. Arrays are Java’s egg trays: many values, ONE type, numbered from ZERO, fixed at birth.

🔎 Motivating questionWhy not carry 30 eggs home in your bare hands?

Objectives

  • Create an array
  • Explain fixed length
  • Read elements by index

Needs first: Debugging and Reading Errors

1 Start with an analogy

Real life first, code second.

The egg tray. Twelve fixed slots, slot 0 first. Need thirteen eggs? Buy a bigger tray (new array) or switch to an expandable basket (ArrayList, Stage 6) — the tray itself NEVER stretches.

⚠️ Where the analogy breaksWhere it breaks: eggs vary; array slots CANNOT. One tray, one type — ints and Strings never share. And trays don’t wash themselves: unused slots hold defaults (0, false, null), not “empty”.

2 The concept, plainly

One idea at a time, words before jargon.

Create sized: int[] a = new int[3]; (three zeros) or pre-filled: int[] a = {10, 20, 30}; Either way the length is FIXED forever: a.length.

Slots are numbered 0 to length−1. Read with a[i], write with a[i] = v. The box brackets mean “slot number”.

Arrays are OBJECTS: the variable holds a reference to the tray (heap!), not the eggs. Copying the variable shares the tray — the references lesson strikes again.

Declaration trivia that matters: int[] a (preferred) vs int a[] (legal relic) — same thing. And a.length has NO brackets: it is a field, not a method.

⚙️ Tech details — precise facts
  • new int[3] zero-fills: {0,0,0}. Object arrays null-fill: new String[3] is {null,null,null} — touching [0].length() crashes.
  • Arrays are covariant but checked: String[] IS an Object[], yet storing an Integer throws ArrayStoreException at runtime. (Generics later fix this properly.)
  • int[] a = null; is a slip to nowhere — a[0] on it is NullPointerException, not “empty array”.

Step at your pace. Text explains every move.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
public class Main {
  public static void main(String[] args) {
    int[] eggs = {10, 20, 30};
    System.out.println("slots = " + eggs.length);
    System.out.println("first = " + eggs[0]);
    eggs[1] = 99; // swap slot 1
    System.out.println("swapped = " + eggs[1]);
    System.out.println("last = " + eggs[eggs.length - 1]);
  }
}
▶ Output slots = 3 first = 10 swapped = 99 last = 30
  • length is 3 — born that way, stays that way.
  • Slot 0 reads 10; slot 1 gets overwritten with 99.
  • Last slot is ALWAYS index length − 1.
▶️ Run it yourselfSave exactly as Main.java, then javac Main.java and java Main. Every full program in this course works this way.
💡 Why this output?A fixed tray of 3: slots read and written by number; the length never moves.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: int[] a = new int[-2];Why: A negative tray is nonsense — NegativeArraySizeException at runtime.
✅ Fix: Sizes are zero or positive. Always.
❌ Mistake 2: Expecting the tray to grow: a[3] = 7 on length 3.Why: Fixed means fixed — slot 3 does not exist and never will.
✅ Fix: Build a bigger array (copy over) or use ArrayList.
❌ Mistake 3: int[] a; then a[0] immediately.Why: Declared but never built — a is null, and null has no slots.
✅ Fix: a = new int[3]; FIRST, then touch slots.
❌ Mistake 4: int a[] = new int[3]; confusion about style.Why: Legal but backwards-looking; modern code writes the brackets with the TYPE.
✅ Fix: int[] a — brackets on the type, always.

9 Takeaways + next step

  • One type, numbered from 0, fixed at birth.
  • length counts slots; last index is length − 1.
  • Arrays are heap objects; variables are slips.
  • new zero/null-fills every slot.
