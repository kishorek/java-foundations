StringBuilder

Stage 4 Concept ⏱ 12 min 📖 Glossary

StringBuilder is the whiteboard for text: scribble, append, erase in place — then photograph it (toString) when the final text is ready.

🔎 Motivating questionHow do you collect 1,000 signatures without shuffling 1,000 papers?

Objectives

  • Build text in a loop
  • Use append and toString
  • Choose StringBuilder vs +

Needs first: String Immutability

1 Start with an analogy

Real life first, code second.

The whiteboard list. Append one more line per visitor, erase typos in place, photograph the board at closing time for the printed record (String). One board, zero photocopies.

⚠️ Where the analogy breaksWhere it breaks: whiteboards are NOT for strangers to share across threads (not synchronized — fine for our single-thread apps) and a Builder is NOT a String: handing sb where text is wanted fails to compile.

2 The concept, plainly

One idea at a time, words before jargon.

Cycle: new StringBuilder() → chain .append(x) (any type!) → finish with .toString(). The SAME object grows throughout.

More tools: length(), charAt/setCharAt, delete(a,b), insert(at, x), reverse() — all editing the one board in place.

Rule: loop-built or heavily-edited text → Builder. One-off joins of a FEW pieces → plain + is fine and reads better.

Convert explicitly: String done = sb.toString();. Comparing needs the photo too: sb.toString().equals("...") — Builder’s own equals is identity.

⚙️ Tech details — precise facts
  • append returns THIS (the same builder), enabling chains: sb.append(a).append(b). No new objects per link.
  • Builders pre-size a capacity buffer (default 16 + growth) so appends rarely reallocate — the engineering behind the speed.
  • Need thread-safe sharing? StringBuffer is the synchronized twin — slower, rarely needed. Default to Builder.

3 Watch it move: Whiteboard workflow

Step at your pace. Text explains every move.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
public class Main {
  public static void main(String[] args) {
    StringBuilder sb = new StringBuilder();
    for (int i = 1; i <= 3; i++) {
      sb.append(i).append(" ");
    }
    System.out.println("built = " + sb.toString());
    sb.reverse(); // edits the SAME board, in place!
    System.out.println("flipped = " + sb.toString());
  }
}
▶ Output built = 1 2 3 flipped = 3 2 1
  • One object absorbs all three appends.
  • toString photographs the board.
  • reverse flips the board itself — no copy.
▶️ Run it yourselfSave exactly as Main.java, then javac Main.java and java Main. Every full program in this course works this way.
💡 Why this output?Appends mutate the single builder; reverse flips it in place; each photo shows the current board.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: String s = sb; — type mismatch.Why: A Builder is NOT a String, however similar they feel.
✅ Fix: Photograph it: String s = sb.toString();
❌ Mistake 2: + chains inside a big loop “because shorter”.Why: Shorter to type, quadratic to run — copies every round.
✅ Fix: One builder outside, appends inside.
❌ Mistake 3: sb.equals("...") to compare content.Why: Builder never overrode equals — identity again.
✅ Fix: Compare the photo: sb.toString().equals("...").
