Project Structure, Maven & Dependencies

Stage 6 Concept ⏱ 15 min 📖 Glossary

Maven is your project manager: standard shelves, one recipe card (pom.xml), automatic ingredient fetching (JUnit arrives alone). New teammates find everything instantly.

🔎 Motivating questionWhy do all supermarkets shelve milk in similar places?

Objectives

  • Lay out src/main/java
  • Read pom.xml
  • Add a dependency

Needs first: Basic Unit Testing

1 Start with an analogy

Real life first, code second.

The standard store. src/main/java (fresh food), src/test/java (taste spoons), pom.xml (the shopping list). mvn test means “taste EVERYTHING”. Any clerk finds milk on day one.

⚠️ Where the analogy breaksWhere it breaks: managers NEED their list. Delete pom.xml and there are no ingredients, no build, no tests — an empty store. Commit it, guard it, review it.

2 The concept, plainly

One idea at a time, words before jargon.

Layout: src/main/java/com/shop/App.java (product), mirrored tests in src/test/java, recipe card pom.xml at the root.

Dependencies arrive by declaration: a junit-jupiter block fetches tests automatically. mvn test compiles and tastes; mvn package builds the shippable jar.

Coordinates: groupId (your aisle, com.shop) + artifactId (product, tasks) + version. Pin maven.compiler.release 17 so builds behave identically everywhere.

Scopes matter: test-scoped deps (JUnit) ship in NO jar — spoons stay in the kitchen, never in customer boxes.

⚙️ Tech details — precise facts
  • Maven Central hosts nearly every Java library: declare, download, done. Versions pin reproducibility — ranges invite mystery breakage.
  • The wrapper (mvnw) pins the Maven ITSELF per project — teammates skip “works on my Maven” entirely.
  • Gradle is the alternative (faster, scripted builds); Maven wins beginners with convention-over-configuration. Either beats bare javac past one file.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

pom.xmlXML
<!-- pom.xml essentials -->
<project>
  <groupId>com.shop</groupId>
  <artifactId>tasks</artifactId>
  <version>1.0</version>
  <properties>
    <maven.compiler.release>17</maven.compiler.release>
  </properties>
  <dependencies>
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>5.10.0</version>
      <scope>test</scope>
    </dependency>
  </dependencies>
</project>
▶ Output mvn test runs green, reproducibly.
  • Java 17 pinned for identical builds.
  • JUnit fetched by declaration.
  • test scope: spoons never ship.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: Code scattered in random folders.Why: Nobody — including future you — finds the milk.
✅ Fix: Follow src/main/java mirroring packages.
❌ Mistake 2: JUnit jar emailed around.Why: Version chaos across machines.
✅ Fix: Declare it in pom; Maven fetches identically.
❌ Mistake 3: Default Java level with modern syntax errors.Why: Old release gatekeeps new features.
✅ Fix: maven.compiler.release set to 17.
