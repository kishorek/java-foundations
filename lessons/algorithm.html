What Is an Algorithm?

Stage 1 Concept ⏱ 12 min 📖 Glossary

An algorithm is a recipe strict enough for a machine: finite steps, a clear order, and a definite end. Every program you will ever write is one or more algorithms.

🔎 Motivating questionHow would you teach a friend who has never been to your street to reach your door, using only a phone call?

Objectives

  • Define algorithm
  • Write steps for a daily task
  • Spot vague vs precise steps

Needs first: What Is Programming?

1 Start with an analogy

Real life first, code second.

Morning routine: alarm → brush → dress → eat. Same order daily, ends when you leave. A loop-free algorithm feels exactly like this — steps you could chant.

⚠️ Where the analogy breaksWhere it breaks: “get dressed nicely” works for humans and fails for machines. “Nicely” is an opinion, not a step. Algorithms need testable steps like “put on the blue shirt”.

2 The concept, plainly

One idea at a time, words before jargon.

An algorithm takes input, follows clear steps in order, and ends with output. “Sort these 5 cards” with written steps qualifies; “be creative” does not.

Good steps are unambiguous (exactly one meaning), ordered (step 2 needs only steps before it), and finite (they always stop). Miss any one and it is not an algorithm.

Programmers judge algorithms by correctness first, then by step count: does it always give the right answer, and roughly how many steps does it take as input grows? That “how many steps” idea is called complexity, and you will feel it with loops and searching later.

Algorithms live above any language. The max-of-two idea below works identically in Java, Python, or pseudocode — only the spelling changes.

⚙️ Tech details — precise facts
  • An algorithm must terminate for every allowed input, not just the examples you tried. “Keep guessing” is not an algorithm.
  • Steps must be effective: simple enough that the follower can actually do them. “Teleport the cheese” is unambiguous but not effective.
  • Writing the steps in plain words before coding is called pseudocode — the professional habit this lesson is really teaching.

3 Watch it move: Vague vs exact

Step at your pace. Text explains every move.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
public class Main {
  public static void main(String[] args) {
    int a = 7;   // input
    int b = 4;   // input
    int max;     // will hold the answer
    if (a > b) {
      max = a;
    } else {
      max = b;
    }
    System.out.println(max); // output: 7
  }
}
▶ Output 7
  • Steps run in order: store, compare, pick, print.
  • The if is a decision point — still an exact step.
  • It always ends after printing: finite.
▶️ Run it yourselfSave exactly as Main.java, then javac Main.java and java Main. Every full program in this course works this way.
💡 Why this output?Compare 7 > 4: true, so max = 7. The else branch is skipped. Any two numbers reach the print — finite and exact.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: “Step 3: do the needful.”Why: Vague verbs cannot execute on any machine.
✅ Fix: Replace with a measurable action: “add 1 spoon of sugar, stir 10 times.”
❌ Mistake 2: Forgetting the stop condition (“keep stirring”).Why: An endless procedure is not an algorithm and bakes a real program into a frozen one.
✅ Fix: Add an end: “stir 10 times, then stop.”
❌ Mistake 3: Steps in the wrong order (“bake, then mix”).Why: Later steps need results that do not exist yet.
✅ Fix: Number the steps; check each one needs only earlier results.

9 Takeaways + next step

  • Algorithm = exact steps + order + guaranteed end.
  • Each step must be testable by a literal follower.
  • Order matters; each step uses only earlier results.
  • Pseudocode first, code second — always.
