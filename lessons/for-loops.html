for Loops

Stage 3 Concept ⏱ 16 min 📖 Glossary

for repeats with a counter: start, keep-going check, step. Perfect when you know how many times.

🔎 Motivating questionHow would you instruct “clap 5 times” without writing “clap” 5 times?

Objectives

  • Write a counted for loop
  • Trace init, check, update
  • Avoid off-by-one

Needs first: switch Statements and Expressions

1 Start with an analogy

Real life first, code second.

Washing machine: set 5 cycles (init i=0), check “done?” (i<5), run + tick (i++). Same three parts every load.

⚠️ Where the analogy breaksWhere it breaks: machines stop alone. Code with i-- instead of i++ may never stop — always verify the check moves toward false.

2 The concept, plainly

One idea at a time, words before jargon.

for (int i = 0; i < 5; i++): init once, check each round, update after.

Index starts 0; i < n runs n times (0..n-1). <= runs n+1 — classic off-by-one.

Body in braces; use i inside: print(i).

3 Watch it move: Washing cycles

Step at your pace. Text explains every move.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
for (int i = 1; i <= 3; i++) {
  System.out.println("Cycle " + i);
}
System.out.println("Done");
▶ Output Cycle 1 Cycle 2 Cycle 3 Done
  • i=1, check ≤3, run, i++.
  • Runs for 1,2,3 then stops.
  • Done prints once after.
💡 Why this output?Three passes, then i=4 fails check, exit to Done.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: for (i = 0; i <= 5; i++) expecting 5 runsWhy: Runs 6 (0..5).
✅ Fix: Use i < 5 for 5 runs.
❌ Mistake 2: Forgetting i++Why: Check never changes → infinite.
✅ Fix: Always update toward exit.
❌ Mistake 3: Using i after loop declared insideWhy: Scope ends at }.
✅ Fix: Declare before if needed outside.

  • for = init; check; update.
  • i < n runs n times.
  • Update must approach exit.
