Nested Conditions

Stage 3 Concept ⏱ 12 min 📖 Glossary

Real decisions stack: inside “is it the weekend?” sits “is it sunny?”. Nesting handles layered reality — but each level multiplies the paths you must test, so flatten whenever you can.

🔎 Motivating questionWhen is a box inside a box clearer than two boxes side by side?

Objectives

  • Nest ifs safely
  • Flatten with &&
  • Trace nested paths

Needs first: if, else if, and else

1 Start with an analogy

Real life first, code second.

Russian dolls. The outer doll asks “weekend?”; only if YES do you open it and find “sunny?” inside. Two levels read fine; five dolls deep and nobody remembers which doll they are in.

⚠️ Where the analogy breaksWhere it breaks: dolls always fit together perfectly. Nested ifs hide paths EXPONENTIALLY — 3 levels ≈ 8 paths to test, and untested paths are where bugs breed.

2 The concept, plainly

One idea at a time, words before jargon.

Nesting = an if inside an if. The inner question is asked ONLY when the outer answer is true; otherwise the whole inner world never happens.

Flatten when the inner needs nothing else: if (a && b) replaces two levels with one, halving the paths. Professionals flatten aggressively.

The dangling else rule: an else pairs with the NEAREST open if. Without braces, “which if does this else belong to?” becomes a riddle — always brace nested code.

Trace nested code with a path table: list every outer/inner true-false combo and the line each combo reaches. If you cannot enumerate the paths, the nesting is too deep.

⚙️ Tech details — precise facts
  • Cyclomatic complexity roughly counts paths through code; each if/loop/case adds one. Pros keep methods near 10 — deep nesting blows past it fast.
  • Guard clauses (early return on bad input) flatten nesting without &&: reject first, then the main logic sits at depth one.
  • Flattening with && is valid only when the inner block has NO else of its own — an inner else needs real nesting.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
public class Main {
  public static void main(String[] args) {
    boolean weekend = true;
    boolean sunny = false;
    if (weekend) {
      if (sunny) {
        System.out.println("Picnic");
      } else {
        System.out.println("Museum");
      }
    } else {
      System.out.println("Work");
    }
  }
}
▶ Output Museum
  • Outer true → step inside.
  • Inner false → its else prints Museum.
  • Braces make every pairing unambiguous.
▶️ Run it yourselfSave exactly as Main.java, then javac Main.java and java Main. Every full program in this course works this way.
💡 Why this output?Weekend true opens the outer doll; sunny false selects the inner else. “Work” needed outer false.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: Dangling else, braceless: if (a) if (b) X; else Y;Why: The else secretly belongs to the INNER if — readers (and you, later) will misread it.
✅ Fix: Brace every nested if, no exceptions.
❌ Mistake 2: Five levels of nesting “to be safe”.Why: 32 paths, most untested — a bug farm with extra steps.
✅ Fix: Flatten with &&, or guard-clause the failures out early.
❌ Mistake 3: Checking inner details before validating the outer.Why: Null or empty outer data detonates before the inner question matters.
✅ Fix: Outer validates first: null-checks live OUTSIDE.

9 Takeaways + next step

  • Nesting = a choice inside a choice.
  • Flatten with && whenever the inner has no else.
  • Braces always — dangling else is a trap.
  • Count paths; too many means restructure.
