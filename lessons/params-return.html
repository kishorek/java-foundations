Parameters and Return Values

Stage 3 Concept ⏱ 15 min 📖 Glossary

Parameters are order slips going IN; return is the served plate coming OUT. void methods shout “done!”; value methods hand you something to use.

🔎 Motivating questionHow does ONE kitchen serve “less spicy, extra rice” to table 3 and “extra spicy” to table 7?

Objectives

  • Pass parameters
  • Return values with return
  • Tell void from value methods

Needs first: Methods

1 Start with an analogy

Real life first, code second.

The service counter. Each slip lists dish + tweaks (parameters: paneer, spice 2). The kitchen returns a plate (return value) or just shouts “done!” (void). Same kitchen, different slips, different plates.

⚠️ Where the analogy breaksWhere it breaks: kitchens guess missing details (“spice 2-ish?”). Java REFUSES — wrong count or wrong types of arguments is a compile error, not a guess. Precision in, precision out.

2 The concept, plainly

One idea at a time, words before jargon.

Parameter = the slot in the DEFINITION (int a). Argument = the value at the CALL (4). Types, order, and count must all match.

return value; sends ONE value back to the caller and exits immediately — code after return never runs. The caller should CATCH it: int s = add(4, 5);

void methods return nothing (a bare return; just exits early). Java methods return AT MOST one value — need more? Pack them in an array or object (later).

Arguments are COPIED in (pass-by-value): changing a parameter inside never touches the caller’s variable. For primitives this is absolute; objects share the house (references lesson).

⚙️ Tech details — precise facts
  • Signature matching is compile-time: add(4) or add("x", "y") fails BEFORE running. Read the error — it names the expected types.
  • An ignored return value compiles fine but wastes work: add(4, 5); alone computes 9 and drops it. Catch or use it.
  • return; (bare) is legal ONLY in void methods, as an early exit. Value methods must return a value on EVERY path.

3 Watch it move: Order slip in, plate out

Step at your pace. Text explains every move.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
public class Main {
  static int add(int a, int b) {
    return a + b; // serve the plate, exit now
  }

  public static void main(String[] args) {
    int s = add(4, 5); // argument values 4, 5 fill slots a, b
    System.out.println(s); // 9
    System.out.println(add(10, 20)); // 30, used directly
  }
}
▶ Output 9 30
  • a, b are slots; 4, 5 are the filled-in values.
  • return sends 9 back and exits add instantly.
  • s catches the plate; the second call feeds println directly.
▶️ Run it yourselfSave exactly as Main.java, then javac Main.java and java Main. Every full program in this course works this way.
💡 Why this output?First call computes 4 + 5 and stores 9 in s; second call computes 30 inside the print.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: add(4) — one argument missing.Why: An unfilled slot: the compiler rejects the call outright.
✅ Fix: Fill every slot: add(4, 5).
❌ Mistake 2: add(4, 5); alone, ignoring the 9.Why: Compiles, computes, drops the plate on the floor.
✅ Fix: Catch it: int s = add(4, 5); — or use it directly.
❌ Mistake 3: return; inside an int method.Why: Value methods must serve the declared type on ALL paths.
✅ Fix: return a + b; — always a value of the right type.
❌ Mistake 4: Expecting TWO return values.Why: Java serves one plate per method, no trays.
✅ Fix: Pack multiples in an array or a small object (later stages).

9 Takeaways + next step

  • Parameters in, return out — matched exactly.
  • Catch the return value or lose the work.
  • One return value max; bare return only in void.
  • Arguments are copied; parameters are private.
