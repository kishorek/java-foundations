Traversing and Updating Arrays

Stage 4 Practice ⏱ 15 min 📖 Glossary

Visiting every slot in order — to print, sum, or upgrade — is called traversing. Loops are the tour bus, and Java runs two models: the counting bus (needs the seat NUMBER) and the sightseeing bus (just greets each passenger).

🔎 Motivating questionHow do you water 20 plants in a row without missing one or drowning one twice?

Objectives

  • Loop with for and for-each
  • Update elements in place
  • Sum and transform arrays

Needs first: Array Indexing and Bounds

1 Start with an analogy

Real life first, code second.

The tour bus with numbered seats. The classic for counts seats (needs the INDEX to repaint them); for-each just greets each passenger (no index, no repainting). To CHANGE seats, you need the counting bus — photos can’t move furniture.

⚠️ Where the analogy breaksWhere it breaks: for-each hands you a PHOTO of each primitive, not the seat. Writing on the photo (v += 5) changes nothing in the tray — the classic “why didn’t my array change?!” mystery.

2 The concept, plainly

One idea at a time, words before jargon.

Classic for when you need the index or must WRITE: a[i] = ..., a[i] *= 2. The index is the address; without it you cannot deliver changes.

for (int v : a) (enhanced for-each) when you only READ: sum += v, print(v). Simpler, bounds-safe by construction, preferred for reading.

v is a COPY for primitives (editing it is scribbling on a photo) — but for OBJECTS it copies the slip, so v.setX() WOULD reach the shared house. Same syntax, different physics!

Accumulator pattern: initialize BEFORE the loop (sum = 0), update INSIDE, use AFTER. Forgetting the init is the #1 traversal bug.

⚙️ Tech details — precise facts
  • for-each desugars to an index loop (arrays) or an Iterator (collections) — same work, less typing, zero off-by-one surface.
  • You CANNOT get the current index from for-each; you CANNOT remove collection elements in one (use removeIf/iterator — Stage 6).
  • a[i] += 5 reads, adds, and writes back in one line — the standard in-place upgrade idiom.

3 Watch it move: Two tour buses

Step at your pace. Text explains every move.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
public class Main {
  public static void main(String[] args) {
    int[] m = {80, 90, 70};
    int sum = 0;
    for (int v : m) {
      sum += v; // sightseeing: read-only tour
    }
    System.out.println("sum = " + sum);
    for (int i = 0; i < m.length; i++) {
      m[i] += 5; // counting bus: repaint every seat
    }
    System.out.println("first now = " + m[0]);
  }
}
▶ Output sum = 240 first now = 85
  • for-each reads all three into sum = 240.
  • The index loop writes +5 into every slot.
  • First slot: 80 → 85.
▶️ Run it yourselfSave exactly as Main.java, then javac Main.java and java Main. Every full program in this course works this way.
💡 Why this output?The read tour sums without touching; the write tour upgrades each slot in place.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: for (int v : m) v += 5; on an int array.Why: v is a PHOTO — the tray never changes, the loop “works” and achieves zero.
✅ Fix: Write tours need addresses: for (i...) m[i] += 5;.
❌ Mistake 2: for (i = 0; i <= m.length; i++) on tour.Why: The ghost-seat finale crashes the whole trip.
✅ Fix: Strict <: i < m.length.
❌ Mistake 3: int sum; then sum += v (no init).Why: Locals have no defaults — “variable might not have been initialized”.
✅ Fix: int sum = 0; BEFORE the loop.

9 Takeaways + next step

  • Read with for-each; write with index loops.
  • Initialize accumulators BEFORE the loop.
  • Strict < length on every tour.
  • Photos vs slips: know which v is.
