Review: Logic Checkpoint

Stage 3 Review ⏱ 15 min 📖 Glossary

Loops, branches, methods, debugging — the engine room. This checkpoint converts shaky traces into confident, fast, table-driven tracing.

🔎 Motivating questionCan you trace a loop faster than it runs?

Objectives

  • Recall loops and methods
  • Fix weak spots

Needs first: Debugging and Reading Errors

1 Start with an analogy

Real life first, code second.

The match replay. Pause at each whistle (condition), note the score (variables), predict the next play BEFORE resuming. Replays build instinct; instinct builds speed.

⚠️ Where the analogy breaksWhere it breaks: replays don’t build fitness. Trace first, then WRITE fresh loops yourself — watching is not training.

2 The concept, plainly

One idea at a time, words before jargon.

Drill the counters: for counts (i < n from 0), while waits (maybe zero), break/continue reshape (exit-all vs skip-one), do-while guarantees one run.

Drill packaging: parameters IN, return OUT, scope ends at the brace, static calls static (until objects).

Drill debugging: file-colon-line addresses, first-error-first, one-change-per-test, oracles for logic.

Trace template on paper: round | variables | decision | action. Four columns, zero confusion, every time.

⚙️ Tech details — precise facts
  • Off-by-one errors live at BOUNDARIES (< vs <=, 0 vs 1 starts). Test edges: 0, 1, n-1, n — always.
  • Rubber-ducking: narrating code line-by-line aloud catches a remarkable share of logic bugs before any tool runs.
  • Infinite loops announce via fan-plus-freeze; the cure is always “advance the watched value inside the body”.

3 Watch it move: Match replay

Step at your pace. Text explains every move.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
int total = 0;
for (int i = 1; i <= 4; i++) {
  if (i == 3) continue; // round 3 donates nothing
  total += i;
}
System.out.println(total); // 1+2+4 = ?
▶ Output 7 — rounds 1, 2, 4 summed.
  • Skip 3 entirely.
  • Sum 1, 2, 4.
  • Answer: 7.
🔍 Illustrated fragmentKey lines showing the idea — a simplified simulation for learning, not a whole runnable file. Full programs appear in early lessons; here the concept is the star.
💡 Why this output?continue abandons round 3’s addition; 1+2+4 = 7.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: <= vs < miscounts, again.Why: Off-by-one resurrects exactly where you stop watching.
✅ Fix: < n from 0 runs n times. Recite it.
❌ Mistake 2: while with a frozen condition.Why: No advance, no exit — fan concerto.
✅ Fix: Move the watched value inside, every loop.
❌ Mistake 3: Reading the LAST error first.Why: Cascades mislead; ghosts accuse the innocent.
✅ Fix: First error, fix, rebuild. Liturgy.

9 Takeaways + next step

  • Trace with the 4-column table.
  • < n from 0 = exactly n runs.
  • First error first; one change per test.
  • Edges first: 0, 1, n-1, n.
