What Is Source Code?

Stage 1 Concept ⏱ 10 min 📖 Glossary

Source code is the human-readable text you write and edit. The computer later translates it — but humans must read it first, including future you at 2 a.m.

🔎 Motivating questionWhy do chefs write recipes down instead of just filming themselves cooking once?

Objectives

  • Explain source code
  • Read a tiny code sample
  • Tell code from the running app

Needs first: What Is an Algorithm?

1 Start with an analogy

Real life first, code second.

A recipe book versus the meal. The book (source) can be shared, reviewed, corrected, and re-cooked a thousand times. The meal (the running app) disappears after eating.

⚠️ Where the analogy breaksWhere it breaks: you can still eat without the recipe. A computer cannot run untranslated source — the text alone does nothing until it is built. Source is potential, not dinner.

2 The concept, plainly

One idea at a time, words before jargon.

Source code is plain-text instructions in a language like Java. Java files end in .java and contain classes, methods, and statements.

Code obeys strict syntax (spelling and grammar). One missing semicolon can stop the whole translation — the translator has no sense of humor about it.

You always write for two readers: the translator, which is strict but dumb, and humans, who need clear names, layout, and comments. Professionals optimize for the humans.

Code is edited far more than it is written. A typical file is read hundreds of times per change, which is why readability rules in this course are not decoration.

⚙️ Tech details — precise facts
  • Java source is Unicode text; the compiler reads it and produces bytecode files ending in .class.
  • The compiler checks syntax and types before producing anything — a file with one error yields no runnable output at all.
  • By convention, one public class per file, and the file name matches it exactly: Hello lives in Hello.java.

3 Watch it move: Source → translator → app

Step at your pace. Text explains every move.

4 Live code demo

Small, correct Java 17 (LTS) code. Read, trace, copy.

Main.javaJava 17
// Hello.java — source code (human readable)
public class Hello {
  public static void main(String[] args) {
    System.out.println("Hi, future programmer!");
  }
}
▶ Output Hi, future programmer!
  • Line 1 is a comment — for humans only, ignored by the translator.
  • Lines 2–3 wrap the program in a class plus its starting point.
  • Line 4 is the one real instruction.
▶️ Run it yourselfSave exactly as Main.java, then javac Main.java and java Main. Every full program in this course works this way.
💡 Why this output?The translator keeps line 4 as an instruction and discards the comment. Running the result prints the text.

6 Common mistakes (at least 3)

Wrong, why, fixed — learn from realistic slips.

❌ Mistake 1: Trying to fix the running app instead of the code.Why: The running app is output; the cause lives in source. Patching output fixes nothing.
✅ Fix: Change the .java file, rebuild, run again.
❌ Mistake 2: Ignoring one red semicolon error.Why: Translation is all-or-nothing: one error, zero program.
✅ Fix: Read the FIRST error line, fix exactly that, rebuild.
❌ Mistake 3: Names like a1, x2, tmp everywhere.Why: Compiles fine, reads terribly — and code is read far more than written.
✅ Fix: Use total, userName, price.

9 Takeaways + next step

  • Source code is text humans write, read, and edit.
  • Syntax must be exact; comments are free notes.
  • Name things for humans, not just the machine.
  • One public class per file, file name matches it.
