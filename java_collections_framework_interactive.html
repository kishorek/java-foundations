START WITH A PROBLEM

1. Why does Java need a Collections Framework?

Imagine writing a to-do app. You need to store tasks, add new tasks, remove completed ones, find a task, and perhaps process them in order. You could build all the storage logic yourself, but that would be a lot of work.

Analogy: a well-organised kitchen
You don't use one container for everything. Plates go in a rack, ingredients go in labelled jars, and the cooking queue has its own order. Java's Collections Framework gives you several ready-made containers, each designed for a different kind of job.

Data structures

Decide how items are organised: list, set, queue, or key-value map.

Algorithms

Reusable operations such as sorting, searching, reversing, and finding a minimum.

The framework is a group of interfaces, implementations, and algorithms. You choose a useful interface such as List, then create an implementation such as ArrayList.

Core principle: choose a data structure based on what you need to do most often, not just on which class name looks familiar.
THE FAMILY TREE

2. The big family: interfaces and implementations

Think of an interface as a promise about available operations. An implementation is the concrete class that performs those operations.

import java.util.ArrayList;
import java.util.List;

List<String> tasks = new ArrayList<>();
tasks.add("Read");
tasks.add("Practise Java");

The variable is declared as List<String>, an interface type, while the object is an ArrayList<String>, a concrete implementation.

Analogy: USB and the device
A USB port describes a connection standard. Many different devices can use it. In a similar way, code that depends on the List interface can work with different List implementations as long as they support the required operations.

Useful mental map

FamilyCommon implementationsBest mental model
ListArrayList, LinkedListOrdered sequence; duplicates allowed
SetHashSet, LinkedHashSet, TreeSetUnique elements
Queue / DequeArrayDeque, PriorityQueue, LinkedListItems waiting to be processed
MapHashMap, LinkedHashMap, TreeMapKey → value lookup
Small but important detail: Map belongs to the Collections Framework, but it does not extend the Collection interface. A Map stores pairs; a Collection stores individual elements.
FAMILY 1

3. List: an ordered sequence

A List keeps elements in a sequence. It has indexes starting at zero, and it can contain duplicate values.

List<String> shopping = new ArrayList<>();
shopping.add("Milk");
shopping.add("Bread");
shopping.add("Milk");

System.out.println(shopping.get(0)); // Milk
System.out.println(shopping.size()); // 3
Analogy: numbered seats in a cinema
Each position has an index. Seat index 0 is the first seat in the list. Two people could have the same name in the booking list; duplicates are allowed unless your program prevents them.

Common List methods

  • add(value): append an item.
  • get(index): retrieve an item at an index.
  • set(index, value): replace an item at an index.
  • remove(index) or remove(value): remove an item. Be mindful of overloads when using numbers.
  • contains(value): test whether a value exists.
  • size(): number of elements.

ArrayList or LinkedList?

ArrayListLinkedList
Great general-purpose default; fast indexed access in typical use.Implements both List and Deque; can be useful for operations at the ends, but is not automatically faster for all insertions/removals.
Backed by a resizable array.Backed by linked nodes.
For most beginner programs that need an ordered, resizable sequence, start with ArrayList.
FAMILY 2

4. Set: uniqueness without duplicate entries

A Set keeps unique elements. Adding a value already present does not create a duplicate.

Set<String> tags = new HashSet<>();
tags.add("java");
tags.add("beginner");
tags.add("java");

System.out.println(tags.size()); // 2
Analogy: a guest list
The list records who is present, not how many times each person signed up. If you need the number of appearances, use a counter or a Map.
  • HashSet: uniqueness; no guaranteed iteration order.
  • LinkedHashSet: uniqueness while preserving insertion order.
  • TreeSet: unique elements kept in sorted order.
Ordering matters: never depend on HashSet printing items in the order you inserted them. Choose LinkedHashSet or TreeSet when order is part of the requirement.
FAMILY 3

5. Queue and Deque: items waiting their turn

A queue is useful when items need to be processed in a particular order. A common rule is FIFO: First In, First Out. A Deque (double-ended queue) supports adding and removing at both ends.

Analogy: a bakery queue
The first customer to join is normally served first. A queue models that waiting line. A deque is like a line where you can work at either end when your use case requires it.
Queue<String> line = new ArrayDeque<>();
line.offer("Arun");
line.offer("Maya");
line.offer("Kavi");

System.out.println(line.poll()); // Arun
System.out.println(line.peek()); // Maya

Three methods worth learning

  • offer(item): add an item, returning whether it was accepted.
  • poll(): retrieve and remove the head, or return null if empty.
  • peek(): inspect the head without removing it, or return null if empty.
Not every queue is FIFO. A PriorityQueue retrieves elements according to priority/natural ordering rather than simple insertion order. Think emergency triage: the most urgent case may be served first.
Deque<String> history = new ArrayDeque<>();
history.push("Home");
history.push("Products");
System.out.println(history.pop()); // Products

Using push() and pop() makes a deque behave like a stack: Last In, First Out (LIFO). That is useful for undo history and backtracking.

FAMILY 4

6. Map: look up a value by key

A Map stores key-value pairs. Keys are unique; values can repeat.

Map<String, Integer> stock = new HashMap<>();
stock.put("Notebook", 20);
stock.put("Pen", 50);
stock.put("Notebook", 18); // update

System.out.println(stock.get("Notebook")); // 18
System.out.println(stock.getOrDefault("Eraser", 0)); // 0
Analogy: labelled storage bins
The product name is the label (key). The number of items is the value. Updating a product's stock changes the value associated with that key.
  • HashMap: general-purpose key-value lookup; no guaranteed iteration order.
  • LinkedHashMap: preserves insertion order by default.
  • TreeMap: keeps keys sorted.

Loop through every entry

for (Map.Entry<String, Integer> entry : stock.entrySet()) {
    System.out.println(entry.getKey() + " → " + entry.getValue());
}

Use entrySet() when you need both key and value. Use keySet() when you only need keys, or values() when you only need values.

SAFER CODE

7. Generics, iteration and the Iterator

Generics tell Java what kind of objects a collection should hold. They catch many type mistakes at compile time.

List<String> names = new ArrayList<>();
names.add("Maya");
// names.add(42); // compile-time error: Integer is not String
Analogy: labelled containers
A container labelled “Strings only” helps prevent someone from putting a bicycle into a box meant for books. List<String> is that label for the compiler.

Enhanced for loop

for (String name : names) {
    System.out.println(name);
}

This is the easiest way to visit every element when you do not need to manage the position yourself.

What is an Iterator?

An Iterator is an object that walks through a collection one item at a time. It is particularly useful when you need to remove elements safely while iterating.

Iterator<String> iterator = names.iterator();

while (iterator.hasNext()) {
    String name = iterator.next();
    if (name.startsWith("A")) {
        iterator.remove();
    }
}
Avoid removing directly inside an enhanced for loop. Calling names.remove(name) from inside that loop can cause a ConcurrentModificationException for common collections. Use an Iterator's remove(), a suitable removeIf(), or collect items to remove separately.

Algorithms are included too

Collections.sort(names);
Collections.reverse(names);
boolean found = names.contains("Maya");

Collections (with a capital C) is a utility class containing static algorithms for collections. Collection (singular) is an interface in the framework. The names are annoyingly similar, so watch the spelling.

ORDERING

9. Sorting and Comparators

Sometimes you need to arrange objects by a rule. A Comparator tells Java how to compare two objects for ordering.

List<String> names = new ArrayList<>(
    List.of("Kavi", "Arun", "Maya")
);

Collections.sort(names); // natural String order

For objects, define the rule you want:

class Student {
    String name;
    int score;

    Student(String name, int score) {
        this.name = name;
        this.score = score;
    }
}

students.sort(Comparator.comparingInt(s -> s.score));
Analogy: judging a race
The runners are the objects. The comparator is the rule that says who comes first, perhaps lower finishing time first or higher score first. Different comparators can sort the same objects in different ways.

10. Choose a collection based on the requirement

If you need…Start with…Why
An ordered resizable sequence with duplicatesArrayListSimple general-purpose List
Unique values, no ordering requirementHashSetMembership and uniqueness
Unique values in insertion orderLinkedHashSetPreserves insertion order
Key-value lookupHashMapMaps a key to a value
Process items in arrival orderArrayDeque as a QueueQueue-style offer/poll/peek
Stack behaviour: last item firstArrayDeque as a DequePush/pop at one end
Retrieve items by priorityPriorityQueueHead is based on priority/order
Sorted keysTreeMapMaintains key order
Beginner default: use ArrayList for most ordered sequences, HashSet for uniqueness, HashMap for key-value lookup, and ArrayDeque for queue/stack behaviour. Change the implementation when the requirement demands it.
PRACTICE

11. Practice problems

Try each one before revealing the answer.

1. You need a shopping list that preserves order and can contain the same item more than once. Which interface fits?

List<String>, commonly implemented by ArrayList<>.

2. Which collection should you use for a set of unique email addresses?

Set<String>, commonly with HashSet<> when order is irrelevant.

3. In a queue, what do poll() and peek() do differently?

poll() returns and removes the head. peek() returns the head without removing it. Both return null if the queue is empty.

4. Why is Map different from List?

A List stores elements in indexed order. A Map stores key-value pairs and uses keys to look up values.

5. What is the main benefit of List<String> instead of a raw List?

Generics make the expected element type explicit and help the compiler catch wrong-type insertions.

6. Why should you avoid directly removing elements from an ArrayList inside an enhanced for loop?

It can cause a ConcurrentModificationException. Use an Iterator's remove method, removeIf, or a separate removal pass.

7. Which implementation is a good starting point for a FIFO queue?

ArrayDeque used through the Queue interface.

8. What is a Comparator used for?

It defines a comparison rule for ordering objects, such as sorting students by score or names by length.
